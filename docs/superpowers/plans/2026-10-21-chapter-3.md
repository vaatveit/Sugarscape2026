## Review Focus

1. **Lattice too full to place a baby.** Both parents fertile but no empty site around either: no child, no sugar deducted. Test in Task 4.
2. **Dead references.** A child, friend, or combat victim that died earlier in the period must never act, inherit, be inherited from twice, or be counted in friend closeness. Tests in Tasks 2, 3, 5.
3. **One-tribe or tribeless populations.** Tribe metrics with no tagged agents, or with one tribe extinct, return `nan`/0 rather than raising (combat runs end this way). Test in Task 6.
4. **Huge populations.** Large-oscillation runs reach ~1,600 agents; `random_empty_site` and placement must keep working near a full lattice (2,500 sites), and mating near full occupancy must not crash. Test in Task 4.
5. **Statistic edge cases.** `dominant_period` on a flat or extinct series returns `nan`, not an index error. Test in Task 7.

## Decisions this plan makes (all recorded as Config fields or docstrings)

| Topic | Decision | Source |
|---|---|---|
| Fertility | fertile when `fertility_start <= age < fertility_end` and `sugar >= initial_sugar` | p.55, p.57 |
| Child endowment | each parent gives half of **its own initial** endowment; child's `initial_sugar` = the sum | p.55 |
| Child placement | uniformly random among the empty von Neumann sites of either parent; none → no child | our call (p.56 requires one) |
| Child genetics | vision, metabolism, max_age each from a random parent; sex random; fertility ages drawn fresh from the config ranges for its sex | p.56 Table III-1; our call for fertility ages |
| Child tags | per position: copy if parents agree, else fair coin | p.78 |
| Interaction order in an agent's turn | move (or combat) → metabolize → neighbors → S → K → friends | design §Scheduling |
| Inheritance | on death, `max(sugar, 0)` split equally among living children; agents dying in the same end-of-period batch don't inherit from each other | p.67; Kehoe |
| Friends | up to 5; a new neighbor displaces the culturally farthest friend if strictly closer (Hamming distance at encounter time, never re-evaluated); dead friends dropped | p.79–80 |
| Combat eligibility | skip own tribe and occupants with `sugar > attacker.sugar` (App. B wording; equal wealth may be attacked) | p.83, App. B |
| Retaliation | a site is vulnerable if any other-tribe agent other than the victim, within the attacker's vision measured from that site, has `sugar > attacker.sugar + reward` | p.82; Kehoe |
| No safe site | stay and harvest the current site | Kehoe; our call on harvesting |
| Tagged initial tribes | random tag strings resampled until their majority matches the tribe | our call |
| Same-tribe replacement | a dead agent is replaced at a random empty site by a random agent of its tribe | p.86 |
| Combat-run blocks | Blue 20×20 at (0,0), Red 20×20 at (30,30); 270 per block for III-9/10/14, 370 per block for III-12/13 (measured from frame 1 of Animations III-9 and III-12); 200 per block for III-11 ("fix the population at 400") | measured; p.86 |
| Proto-history soup | 100 agents ("small, low density") with S defaults | our call |
| Chapter III endowments | 50–100 unless a figure states otherwise (p.57); III-8 culture run and combat runs 25–50 (the Chapter II default) | p.57; Ch II finding |

def combat_candidates(model, agent) -> list[tuple[int, int, int, float, Agent | None]]
    # (x, y, distance, reward, victim): current site first, then random direction order out to vision;
    # skips own-tribe occupants and occupants with sugar > agent.sugar (sight continues past them)
