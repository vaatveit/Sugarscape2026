# Sugarscape Chapter V Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add immune systems, diseases, the immune response and transmission rules (together, E), immune genotypes passed through sexual reproduction, and the metabolic fee of illness; reproduce Chapter V's results: society rids itself of disease with a small disease list (Animation V-1) and sustains an endemic level with a large one (Animations V-2, V-3).

**Architecture:** Extends `main`. A new `sugarscape/rules/disease.py` holds the string operations (nearest substring, immune step) and the rules; the model creates a master disease list, infects the initial population, and runs E at the end of each agent's turn. An agent's effective sugar metabolism (`sugar_burn`) adds the fee per active disease, and metabolism, welfare and MRS all use it, so illness changes behavior (p.143). `stats.disease_metrics` and two experiments complete the chapter.

**Tech Stack:** Python 3.14 (`.venv`), NumPy, matplotlib, pytest.

**Spec:** `docs/superpowers/specs/2026-10-21-sugarscape-design.md` (binding), `docs/book-notes.md` (Chapter V). Earlier outcomes: `docs/replication/chapter-2.md` to `chapter-4.md`.

## Review Focus

1. **Disease as long as the immune system.** A disease must be shorter than the immune string (p.141); Config rejects `disease_length[1] >= immune_length`. Test in Task 1.
2. **Catching a disease twice.** A disease already carried isn't added again and its fee isn't doubled; a disease the agent is immune to isn't contracted (p.145). Test in Task 1.
3. **Memory corruption.** Learning one disease can unlearn another (p.145: 11 and 00 can't both live in a length-3 system); the agent must be able to catch it again, with no infinite loop in the immune step. Test in Task 1.
4. **Genotype vs phenotype aliasing.** Training the phenotype must never change the genotype, and a child's genotype must be a fresh list (p.146). Test in Task 2.
5. **Illness and starvation.** The fee raises sugar burn; an agent can die of the fee; welfare and MRS use the raised burn without errors; disease metrics on an empty population are `nan`, not errors. Tests in Tasks 2 and 3.

## Decisions this plan makes

| Topic | Decision | Source |
|---|---|---|
| Carried diseases | `agent.diseases` holds only active infections (not yet matched). Contracting a disease the agent is immune to does nothing (p.145); a disease is removed the moment the immune system matches it. | p.144–145; Animation V-3 counts (3.41 at start with 10 given) |
| What spreads | Only active infections ("a disease that currently afflicts the agent") | p.145 |
| Immune step | Per carried disease, per period, in order of infection: if it's a substring of the immune system, remove it; else take the leftmost substring with minimum Hamming distance, flip its first differing bit, and remove the disease if it now matches | p.142 fn 11, p.144; Table V-1 (1-bit gap → 1 period of illness) |
| Fee | `disease_fee` (default 1.0) added to sugar metabolism per active disease; applied in metabolism, welfare and MRS; spice metabolism unaffected | p.143 ("hiked by, say, one"; behavior changes); our call on sugar only |
| Turn order | move → metabolize (with fee) → neighbors → S → K → T → L → E (transmission, then immune response; corrected in the final review) | design §Scheduling; p.143 |
| Transmission | For each current neighbor, in random order: one random active disease of the agent, offered to the neighbor (contracted unless immune or already carried); new infections logged as (source, target) | p.145, p.150 |
| Master list | `disease_list` random strings, each of length U{1..10}, drawn from the model's generator at start | p.147 |
| Initial infection | Each initial agent is offered `diseases_per_agent` **distinct** diseases from the list (p.147 says "distinct" for V-2; our call for V-1) | p.147 |
| Immune system | Random 50-bit genotype; the phenotype (trained) starts as a copy | p.146–147 |
| Children | Genotype crossed like tags (agree → copy, else coin flip), phenotype a copy, no diseases | p.146 |
| Replacements | Random genotype, no diseases | p.146 by analogy |
| Mutation | None (rates are zero in the book's runs, fn 15) | p.146 fn 15 |
| Runs V-1, V-2 | Chapter II landscape and agents (400, vision 1–6, metabolism 1–4, endowment 25–50, immortal), G1, M, E | p.147 ("as in Chapter II") |

**Interfaces:**
- `disease.transmit(model, agent) -> None`: for each current neighbor in random order, offer one random disease from `agent.diseases`; on a new infection append `(agent, neighbor)` to `model.infection_log`.
