# Sugarscape in Julia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Julia port of the sugarscape model that runs every `Config` experiment in the registry, at regular and
xl size, plus a report comparing it with the Python model for statistical agreement, book-target status and speed.

**Architecture:** Python stays the single source of truth for the registry: an exporter writes `julia/registry.toml`.
The Julia package `Sugarscape` (stdlib only) in `julia/` mirrors the Python modules one file per rule family. It is
run by `julia/run.jl`, which writes results in the Python runner's layout to `results-julia[-xl]/`. Python tooling
in `julia/bridge/` (exporter, cross-language scenario fixtures, agreement statistics, report) reuses
`experiments.run` and `replication`. The model is ported and checked chapter by chapter, each chapter compared with
Python's saved results before the next one starts.

**Tech Stack:** Julia 1.13.2 with Random, Statistics, Printf, TOML, SHA, Distributed, Dates, Test (stdlib only).
JuliaFormatter in a separate tools environment. Python 3.14 + numpy (existing) + pytest for the bridge.

**Spec:** `docs/superpowers/specs/2026-10-24-julia-design.md` (commit 8f224bc).

## Global Constraints

- Work happens in the worktree `C:/Projects/Sugarscape2026/.claude/worktrees/julia` on branch `feat/julia`. All
  paths below are relative to it. The Python venv is the main checkout's:
  `PY=C:/Projects/Sugarscape2026/.venv/Scripts/python.exe`.
- **Python results live in the main checkout**: `C:/Projects/Sugarscape2026/results` and `.../results-xl`. They are
  produced by the user's other sessions. This project never runs Python experiments and never writes there.
- No change to anything under `sugarscape/`, `experiments/`, `replication/`, `viewer/`, `tests/` or `flamegpu/`.
- The Julia package uses the standard library only. `julia/Project.toml` is changed only through Pkg
  (`Pkg.add`, `Pkg.develop`), never by hand. Commit `Manifest.toml` too.
- Format with JuliaFormatter, BlueStyle (`julia/.JuliaFormatter.toml`: `style = "blue"`), before every commit:
  `julia --project=julia/tools julia/tools/format.jl`.
- The model is single-threaded. `--jobs J` means J worker processes, one seed at a time each.
- Julia uses `Random.Xoshiro(seed)`, seeded with the registered seed plus k for seed k. Agreement with Python is
  statistical; no numpy-compatible streams.
- Semantics are the Python model's (`sugarscape/model.py`, `sugarscape/rules/*.py`, `sugarscape/stats.py`). Port from
  the source. Free to differ: the RNG, internal list orders, how a uniform choice is made, data layout (design,
  "Free to differ").
- **Keep Python's draw order and gating in founder creation** (`Model._spawn_at`, `_place_initial_population`,
  disease setup, founder ages). Chapter III draws only when their fields are on, after Chapter II's; Chapter IV's
  after those; Chapter V's last. That keeps VI-2 and VI-3 seed k starting from the identical society.
- Coordinates on agents are 0-based `(x, y)` as in Python (x east, y north, y = 0 south). Arrays are 1-based:
  site (x, y) is `A[x + 1, y + 1]`.
- Bit-field limits: Julia refuses `tag_length > 63` and `immune_length > 64` with an `ArgumentError` (the registry
  uses 11 and 50). This is the one place Julia refuses a config Python accepts.
- Metric columns, in this order (46 with `t`): `t, population, mean_vision, mean_metabolism, mean_sugar, gini,
  mean_neighbors, moved, ne_fraction, on_peak_fraction, north_frac_high_vision, north_frac_low_vision, summer_north,
  n_blue, n_red, blue_fraction, sw_blue, sw_red, ne_blue, ne_red, blue_xy, red_xy, blue_advance, red_advance,
  mean_children, best_friend_closeness, friend_closeness, agents_ever, mean_spice, trades, mean_price,
  mean_log_price, price_sd, sugar_traded, spice_traded, mean_foresight, n_loans, n_lenders, n_borrowers, n_both,
  credit_depth, mean_diseases, sd_diseases, fraction_sick, new_infections, diseases_circulating`.
- Agreement rule (spec): four windows; Welch t-test per (experiment, metric, window); Benjamini–Hochberg at
  q = 0.01 over every test in one report; extinction by Fisher's exact test in the same correction; fewer than two
  values on a side → untestable, never flagged.
- Checks: Julia `julia --project=julia -e "using Pkg; Pkg.test()"`; bridge `cd julia && $PY -m pytest -q`; the
  repository's own suite `$PY -m pytest -q` from the worktree root stays green.

## Review Focus

1. **Extinction mid-run.** VI-1 died out in 3 of 5 Python seeds. With no agents, `step!` must keep running and
   every metric must be NaN (or 0.0 where Python says so: `population`, counts, `mean_children`), never an error.
   Task 4 tests a model with no agents through 3 steps and its metrics row.
2. **A nearly full lattice.** Replacement and childbirth pick uniform empty sites. Rejection sampling must
   terminate and stay uniform when almost every site is taken, and a full lattice must raise as Python does. Task 3
   tests a grid with one empty site and a full grid.
3. **The fullest xl placement.** III-12 at xl puts 37,000 agents per tribe into 40,000 block sites. Building the
   model must succeed without a placement error. Task 9 builds it.
4. **Values Python can't read back.** NaN, ±Inf, -0.0, 1e300, 1e-300 and integers must all survive
   `experiments.run._read_csv`. Task 5 tests `format_value` in Julia and the round trip in Python.
5. **More jobs than seeds, and a seed that throws.** `--jobs 3` with 2 seeds must work. A seed that throws must
   name its experiment and seed, exit non-zero, and leave the folder's old results as they were. Task 5 tests both.

### Task 5: The runner

**Files:**

**Interfaces:**
- Consumes: `load_registry`, `find_experiment`, `to_xl`, `Model`, `step!`, `collect_metrics`, `METRIC_COLUMNS`.
- Produces:
  - `matching_ids(arg, ids)::Vector{String}`, as `experiments.run.matching_ids`.
  - `timed_seed(exp::Experiment, k::Int; xl::Bool)::Tuple{Vector{Vector{Float64}},NamedTuple}`. It returns the rows
    (`t` first, then metrics; t = 0..steps) and `(seed, periods, setup_s, stepping_s, metrics_s, agents_start,
    agents_end)`, timed with `time_ns()` exactly as `experiments.run.timed_seed` divides the work.
  - `warm_up!(exp::Experiment)::Float64` runs the regular config for 2 untimed periods with metrics, once per
    process (a module-level flag), and returns the seconds it took (0.0 when already warm).
  - `format_value(x)::String`: integers as digits; NaN `"nan"`; `"inf"` / `"-inf"`; other floats by Julia's
    shortest `string(x)` (which Python's `float()` parses).
  - `run_experiment(exp; seeds=exp.seeds, jobs=1, out, xl=false, note="")`. It computes every seed first; only then
    it deletes old `seed*.csv` and writes `seed{k}.csv`, `timing.csv`, `machine.txt` and `fingerprint.txt`. The
    fingerprint is `"julia\n" * (xl ? exp.xl_fingerprint : exp.fingerprint)`. `jobs > 1` uses
    `addprocs(min(jobs, seeds))`, `@everywhere using Sugarscape`, and `pmap(k -> ..., 0:seeds-1)` (batch_size 1),
    then `rmprocs`. A failing seed throws an error naming the experiment id and seed.
  - `machine.txt` lines: `julia = VERSION`, `platform = Sys.KERNEL Sys.MACHINE`, `processor = Sys.cpu_info()[1].model`,
    `jobs = J`, `threads = Threads.nthreads()`, `warm_up_s = ...` (per worker, comma-separated); with J > 1
    `note = timings taken with --jobs J share the processor`; with `--note`, `user_note = TEXT`.
  - `julia/run.jl`: `julia --project=julia julia/run.jl <id-or-prefix> [--seeds N] [--jobs J] [--out DIR] [--xl]
    [--note TEXT]`. The default out is `results-julia` or `results-julia-xl`, relative to the current directory.
    No match is an error with exit code 2.

### Task 7: Agreement statistics and the report

**Files:**
- Create: `julia/bridge/agreement.py`, `julia/bridge/report.py`, `julia/bridge/tests/test_agreement.py`,
  `julia/bridge/tests/test_report.py`

**Interfaces:**
- Consumes: `experiments.run.load_results`, `result_dir`, `fingerprint`, `TIMING_COLUMNS`;
  `replication.report.evaluate`, `_fmt`; `replication.targets.TARGETS`.
- Produces, in `agreement.py`:
  - `t_sf(t: float, df: float) -> float`, the upper tail of Student's t (regularized incomplete beta by continued
    fraction).
  - `welch(a, b) -> tuple[float, float, float]`: `(t, df, p_two_sided)`.
  - `benjamini_hochberg(p: list[float], q: float) -> list[bool]`.
  - `fisher_exact(a: int, b: int, c: int, d: int) -> float`: two-sided, summing tables no more likely than the
    observed one, within a relative 1e-7.
  - `windows(steps: int) -> list[tuple[int, int]]`: inclusive t ranges `k*(steps+1)//4 .. (k+1)*(steps+1)//4 - 1`.
  - `@dataclass Test(experiment, metric, window: int | None, kind, p, n_py, n_jl, mean_py, mean_jl, sd_py,
    flagged=False)`. `kind` is `"tested"`, `"identical"` (equal constants on both sides: not a difference, not in
    the correction), `"constant-differs"` (each side constant, different: always flagged, not in the correction),
    `"untestable"` (fewer than 2 values on a side), or `"extinction"` (`window` None; Fisher on the seeds with
    `population == 0` at the last row).
  - `eligible(metric, py_runs, jl_runs) -> bool`: False when every value on both sides is NaN, or every non-NaN value
    on both sides is one constant.
  - `compare_experiment(exp_id, py_runs, jl_runs) -> list[Test]`, and `flag(tests, q=0.01) -> None`, which marks the
    BH survivors among `tested` and `extinction` (and all `constant-differs`).
- Produces, in `report.py`: `python -m bridge.report [--xl] [--only PREFIX] [--julia DIR] [--python DIR]`. Defaults:
  `REPO_ROOT/results-julia[-xl]` and `PY_RESULTS/results[-xl]`. It writes `<julia dir>/REPORT.md`, with:
  1. inputs: per experiment, missing / stale / untimed on each side (Julia stale = `fingerprint.txt` is not
     `"julia\n"` plus the current Python fingerprint);
  2. the verdict line: agrees or not (flags + status changes = 0);
  3. flags, worst first: experiment, metric, window, means, difference in units and in Python SDs, p, adjusted
     rank;
  4. untestable windows, counted per experiment;
  5. book targets (regular only): both statuses, and the status changes, as `gpu_report.write_comparison`;
  6. speed: per experiment, mean `setup_s`, `stepping_s/periods`, `metrics_s/(periods+1)`, agents at start and end,
     the Julia/Python stepping ratio, and each side's `jobs` and `user_note` from `machine.txt`, under a line
     saying development timings are uncontrolled; Julia-only rows where Python has no `timing.csv`; the median
     ratio.

    t*t)))` for t in (0.3, 1.7, 6.0); `t_sf(2.228138852, 10) == approx(0.025, abs=1e-7)`; `welch([1,2,3,4,5],
