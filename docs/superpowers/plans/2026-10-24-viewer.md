# Sugarscape Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser viewer for one run of a registered experiment. It shows the 50×50 grid colored by sugar and spice, the agents drawn in their cells and encoded by tribe and wealth, a population chart, and play, pause and scrub controls.

**Architecture:** A new top-level package `viewer/`.
- **Recording:** `viewer/frames.py` captures a compact, exact `Frame` of a `Model` after each period, and `viewer/run.py` owns one run (model, frame list, lock) and steps it on demand.
- **Server:** `viewer/server.py` is a standard-library `ThreadingHTTPServer` that serves a JSON API and the static page, and `python -m viewer` starts it.
- **Page:** plain ES modules on a canvas. `viewer/static/encoding.mjs` holds every visual encoding as pure functions, tested with `node --test`; `viewer/static/app.mjs` draws and handles the controls.

**Tech Stack:** Python 3.14 (`.venv`) with NumPy and the standard library (`http.server`, `json`, `threading`, `webbrowser`); pytest; plain JavaScript in the browser; Node 25 (`node:test`, `node:assert`) for the encoding tests. No new packages.

**Spec:** `docs/superpowers/specs/2026-10-24-viewer-design.md` (binding). Model code: `sugarscape/model.py`, `sugarscape/agent.py`, `sugarscape/landscape.py`; seeding as in `experiments/run.py:66-69`.

## Global Constraints

- **The model is read-only.** No file under `sugarscape/`, `experiments/` or `replication/` changes, so every experiment fingerprint and the 303 existing tests stay as they are.
- **Exact values.** Every number the page shows or encodes comes from the model unchanged. Storage may drop to float32 only when the round trip is exact.
- **Fixed encodings.** The cell blend, wealth bands, band sizes and colors and tribe colors are constants. Nothing rescales per frame.
  - Cell levels are scaled by the run's highest capacity, separately for sugar and for spice.
  - Wealth bands: < 10, 10–30, 30–100, 100–300, ≥ 300, with lower bounds inclusive.
- **Network.** The server binds `127.0.0.1` only.
- **Dependencies.** Standard library and NumPy only on the Python side; no npm packages and no build step.
- **Docs.** Context7 has been checked for `http.server` (`ThreadingHTTPServer`, `send_header`/`end_headers`) and `node --test` (quoted glob patterns). Check again before using any other API from either.
- **Git.** Branch `feat/viewer` off `main`, with one commit per task once the user approves execution. Nothing is pushed. LF line endings.

## Review Focus

1. **Path traversal through the static route.** `GET /static/../pyproject.toml` (also URL-encoded as `%2e%2e`) must return 404, never a file outside `viewer/static/`. Test in Task 2.
2. **Windows MIME types.** On Windows, `mimetypes` can read `.js`/`.mjs` from the registry as `text/plain`, and browsers then refuse ES modules. The server sends `text/javascript` from its own table. Test in Task 2.
3. **Sugar-only runs.** Spice capacity is 0 everywhere, so the spice term divides by a zero maximum. `cellColor` must return pure sugar shades with no NaN. Test in Task 3.
4. **Extinction.** A run whose population reaches 0 keeps stepping and serving frames with no agents, and the chart shows 0. Test in Task 1.
5. **Concurrent requests.** Playback prefetch and a slider drag can ask for new periods at the same moment. The run must step each period exactly once, and every reader must see the same frame for a given t. Test in Task 1.

## Decisions this plan makes

| Topic | Decision |
|---|---|
| Storage | Keep every period as a `Frame`. Agent columns are NumPy arrays, and grids use float32 when the round trip is exact (always so for levels in eighths), float64 otherwise. Measured: VI-1, III-8 and IV-14 frames are about 30–40 KB as JSON, and a step takes 1–10 ms. |
| Grid layout | `ravel()` of the landscape's `[x, y]` arrays (C order): cell (x, y) is index `x * height + y`. |
| On-demand stepping | `Run.frame(t)` steps the model up to t when t is past the latest period. Requests more than `LEAD = 50` periods ahead are refused. The page prefetches at most 5 ahead while playing and nothing while paused, so a paused run never grows. |
| Catalog | Experiments whose config is a `Config`, except `TEST-tiny`. Book experiments come first in registry order, then the `VAR-` ones in registry order. |
| Tribes present | `bool(config.tag_length)`. `Agent.tribe` is `None` exactly when there are no tags. |
| Blend constants | White (255, 255, 255), yellow (232, 190, 40), rust (176, 80, 40), weight 0.58: `c = W + 0.58·(s/smax)·(Y − W) + 0.58·(p/pmax)·(R − W)`, each channel rounded half up. Checked: no channel goes below 5.6, and all 33 × 33 drawn colors are distinct (closest pair 2 apart in L1). |
| Band encodings | Colors light to dark: `#fde0c5 #f9a66c #e8603c #b22b28 #5c0f1e`. Radii, as a fraction of the cell: 0.20, 0.28, 0.36, 0.44, 0.52. Tribe colors: red `#d62728`, blue `#1f5fbf`. Neutral (no color attribute): `#333333`. |
| Single session | The server holds one current `Run`, and `POST /api/run` replaces it. |

### Task 2: The HTTP server

**Files:**
- Create: `viewer/server.py`, `viewer/__main__.py`, a placeholder `viewer/static/index.html` (a title and an empty `<main>`; Task 4 replaces it)
- Test: `tests/test_viewer_server.py`

**Interfaces:**
- Consumes: `Run`, `catalog`, `LEAD` from Task 1.
- Produces: `make_server(port: int = 0) -> ThreadingHTTPServer`, bound to `("127.0.0.1", port)`, with the current run at `server.run: Run | None`. Routes:

| Route | Response |
|---|---|
| `GET /` | `static/index.html` |
| `GET /static/<name>` | A file directly inside `viewer/static/`; 404 otherwise |
| `GET /api/experiments` | `catalog()` |
| `POST /api/run` | Body `{"experiment": str, "seed": int}`. Replaces `server.run`; returns `run.info()` |
| `GET /api/frame?t=N` | `frame.to_json()` plus `"latest"` |
| `GET /api/population?from=N` | `{"latest": int, "from": N, "counts": run.populations(N)}` |

  - **Errors** are JSON `{"error": message}`:
    - 400 for a bad body, an unknown experiment, a seed that isn't an int ≥ 0, or a bad or out-of-range `t`;
    - 409 for frame or population requests before any run;
    - 404 for unknown paths;
    - 500 with the exception text if the model raises. The server keeps running.
  - **Content types** come from a fixed table: `.html` → `text/html; charset=utf-8`, `.mjs`/`.js` → `text/javascript; charset=utf-8`, `.css` → `text/css; charset=utf-8`, JSON → `application/json`.
  - `Cache-Control: no-store` on API responses.
  - `python -m viewer` takes `--port` (default 0, a free port), prints `Sugarscape viewer at http://127.0.0.1:<port>/`, and opens it with `webbrowser.open` unless `--no-browser`; Ctrl+C shuts it down cleanly.

  - Requests go through `urllib.request`; error statuses are read from `HTTPError.code` and its JSON body.

### Task 4: The page

**Files:**
- Modify: `viewer/static/index.html`
- Create: `viewer/static/app.mjs`, `viewer/static/style.css`

**Interfaces:**
- Consumes: the Task 2 routes and Task 3's exports. `app.mjs` must not define any encoding of its own: every color, size and legend entry comes from `encoding.mjs`.

**Behavior** (layout and styling are the builder's; the board comes first):
- **Start.** An experiment `<select>` filled from `/api/experiments` (shown as `id — title`), a seed number input (min 0, default 0), and a Start button that POSTs `/api/run`. Beside them:
  - the actual seed and the registered `steps`;
  - the current t, the population, and `latest` ("computed to t = …").
- **Board.** A `<canvas>` of 50 × 50 cells, with y drawn upward (`row = height − 1 − y`).
  - Cells are filled with `cellColor(sugar[i], spice ? spice[i] : 0, sugar_max, spice_max)`, where `i = x * height + y` and the frame's `spice` is null on sugar-only runs.
  - Each agent is a filled circle at its cell center, with radius `SIZE_MODES[size].radius(a) × cell` and color `COLOR_MODES[color].color(a)`.
  - The canvas is sized for the device pixel ratio so it stays crisp.
- **Menus.** "Color by" lists the `COLOR_MODES` whose `available(info)` is true; the default is tribe, else none. "Size by" lists `SIZE_MODES`, defaulting to wealth. Changing a menu redraws the current frame without refetching.
- **Legend.** A swatch grid from `legendCells(sugar_max, spice_max)`, with sugar levels along one axis, spice along the other, and the axes labeled (a single row on sugar-only runs). Below it go the `legend()` entries of the chosen color and size modes.
- **Hover.** Over a board cell, a readout shows `(x, y)`, sugar and spice levels with their capacities (from `info`), and, when the cell is occupied, the agent's id, wealth, sugar, spice, tribe, vision, metabolism, age and sex. Numbers show to two decimals; integers stay as they are.
- **Chart.** A canvas plotting the population for t = 0..latest, kept current through `/api/population?from=<last known + 1>`.
  - The y-axis has labeled ticks, and its maximum may grow.
  - A vertical marker sits at the current t, and clicking sets t to the nearest period ≤ latest.
- **Time.** Play/pause, step −1/+1, a slider (`max = latest`, updated as latest grows), and a speed `<select>` of 1, 2, 5, 10, 20 and 30 periods per second plus "max" (as fast as frames arrive).
  - While playing, the page keeps at most 5 requests in flight ahead of the board.
  - While paused, it sends no frame request past the current t.
  - Frames are cached client-side (a `Map` capped at 300 entries) so scrubbing redraws at once.
- **Errors.** API errors show in a visible status line; the page stays usable.
