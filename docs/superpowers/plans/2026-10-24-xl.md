# Sugarscape xl Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 500×500 "xl" sugarscape for comparing implementations: a committed upscaled map and its generator, a
language-neutral spec, `--xl` in the runner and the viewer, and timing of the Python baseline.

**Architecture:** The map generator (`sugarscape/maps/xl.py`) writes `sugar-map-xl.txt` once; everything else
loads the file. One transform, `sugarscape.xl.to_xl(Config) -> Config`, turns a registered config into its xl
config. The runner and the viewer's `Run` both call it. A new hidden `Config.diffusion_passes` carries the only rule
change xl needs. The viewer gets xl palettes in `encoding.mjs` and a pixel-per-cell painter in a new `board.mjs`.

**Tech Stack:** Python 3.14, numpy, matplotlib (existing), standard library only for the viewer server; plain ES
modules in the browser; pytest and `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-24-xl-design.md` (commit faab6d8).

## Global Constraints

- No new dependencies: numpy and matplotlib on the Python side, nothing on the JS side.
- **No regular run changes:** every registered experiment keeps its config, random stream, result files and
  `fingerprint`. New `Config` fields use `field(default=..., repr=False)`.
- Existing tests are not edited. New behavior gets new tests, in new files or appended to existing files.
- xl applies to sugarscape `Config` experiments only, never to `SchellingConfig` or `RingConfig`.
- The xl map: σ = 0.5 coarse cells (5 fine cells), kernel radius 15, factor 10, levels 1–4, no torus wrapping.
- xl config table (spec): world 500×500, map `sugar-map-xl.txt`, `initial_population` ×100, `vision` (10·lo, 10·hi)
  with every integer in it, `block` all four numbers ×10, `initial_blocks` coordinates ×10 and counts ×100,
  `diffusion_passes` ×100. Everything else unchanged.
- The viewer keeps 500 periods for regular runs and 100 (`KEEP_XL`) for xl runs.
- xl palettes (chosen while planning, all passing the spec's tests on a prototype):
  - `XL_WEIGHT = 0.3`, the smallest tried weight at which all 33×33 eighths draw distinctly (0.25 gives only
    1002 distinct colors);
  - tribes red `#b71c1c` and blue `#1f5fbf`; neutral `#333333`;
  - bands `#b23a0c #a01036 #6d1a7a #3a0c6b #0a0612`, light to dark.
  Every one has at least 3.26:1 contrast against every xl cell. The bands' L* falls 42.0 → 34.2 → 27.8 → 16.6 → 2.2,
  and adjacent bands differ by ΔE76 of at least 16.4.
- Results of xl runs go to `results-xl/` unless `--out` says otherwise.
- Checks: `.venv/Scripts/python -m pytest -q` (346 passed, 169 deselected at the start) and
  `node --test "tests/js/*.test.mjs"` (15 passed at the start).

## Review Focus

1. **A small window:** with fewer than 500 device pixels for the board, the board stays 500 device pixels and the
   page scrolls; no row or column is dropped. Task 8 tests `boardPixels` below 500.
2. **Fullest tribal blocks:** III-12 puts 370 agents per tribe in a 20×20 block, so 37,000 in 40,000 sites at xl.
   The model must build without a placement error. Task 3 builds III-12 at xl.
3. **Old clients and bad input:** `POST /api/run` without `xl` starts a regular run, and a non-boolean `xl` is a 400.
   Task 6 tests both.
4. **Timing under `--jobs 2`:** rows come back from worker processes, one per seed, and the machine note says the
   processor was shared. Task 4 tests it.
5. **Hover at xl:** hover reads `sugar_capacity[x * 500 + y]`, so the info's capacity lists must have 250,000 entries
   in `x * height + y` order. Task 6 tests the length and spot-checks the order.

- [ ] **Step 3: Implement `parse_map`, then `sugarscape/maps/xl.py`.** `parse_map` is `load_map`'s existing body

```python
def signed_distance(region):  # region: bool [x, y]; distances between coarse centres
    w, h = region.shape
    xs, ys = np.meshgrid(np.arange(w), np.arange(h), indexing="ij")
    pts = np.stack([xs.ravel(), ys.ravel()], 1).astype(float)
    dist = np.hypot(pts[:, None, 0] - pts[None, :, 0], pts[:, None, 1] - pts[None, :, 1])
    m = region.ravel()
    d_out = np.where(~m[None, :], dist, np.inf).min(1)
    d_in = np.where(m[None, :], dist, np.inf).min(1)
    return np.where(m, d_out, -d_in).reshape(w, h)


def _axis(n, k):  # fine centres in coarse index units, clamped: (lower index, upper index, weight)
    f = (np.arange(n * k) + 0.5) / k - 0.5
    i0 = np.clip(np.floor(f).astype(int), 0, n - 1)
    t = np.where(f < 0, 0.0, np.where(f > n - 1, 1.0, f - np.floor(f)))
    return i0, np.clip(i0 + 1, 0, n - 1), t


def bilinear(field, k):
    (a0, a1, ta), (b0, b1, tb) = _axis(field.shape[0], k), _axis(field.shape[1], k)
    lo = field[a0][:, b0] * (1 - tb) + field[a0][:, b1] * tb
    hi = field[a1][:, b0] * (1 - tb) + field[a1][:, b1] * tb
    return lo * (1 - ta)[:, None] + hi * ta[:, None]


def gaussian_blur(f, sigma):  # sigma in fine cells; separable, radius int(3 * sigma), edge-replicating
    r = int(3 * sigma)
    k = np.exp(-0.5 * (np.arange(-r, r + 1) / sigma) ** 2)
    k /= k.sum()
    for axis in (0, 1):
        p = np.pad(f, [(r, r) if a == axis else (0, 0) for a in (0, 1)], mode="edge")
        f = sum(w * np.take(p, np.arange(i, i + f.shape[axis]), axis=axis) for i, w in enumerate(k))
    return f


def blurred_levels(capacity, factor=FACTOR, sigma=SIGMA):
    return [gaussian_blur(bilinear(signed_distance(capacity >= lv), factor), sigma * factor)
            for lv in range(1, int(capacity.max()) + 1)]


def upscale(capacity, factor=FACTOR, sigma=SIGMA):
    inside = np.ones((capacity.shape[0] * factor, capacity.shape[1] * factor), dtype=bool)
    fine = np.zeros(inside.shape, dtype=int)
    for level in blurred_levels(capacity, factor, sigma):
        inside &= level > 0  # terraces nest
        fine += inside
    return fine
```
