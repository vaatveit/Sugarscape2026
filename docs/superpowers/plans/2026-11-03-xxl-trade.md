# Sugarscape xxl, stage 5: trade — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Find out whether healthy agents get richer by trading, add an xxl rule (Rule 13) that lets movement count on trade, screen five versions of it, confirm the best, and write the findings into `docs/xxl.md`.

**Architecture:** Rule 13 is three `XxlRules` fields that change the two-good site score (`net_value`, `score`) through `SiteWelfare`, which gains a blend weight and an expected price; the book path is untouched when the rule is off. A trade-readings observer, like the loan trace, records who trades with whom and a per-agent snapshot; a study tool runs arms with it and a report tool reads them against bars fixed before the runs. Runs and the write-up follow.

**Tech Stack:** Julia (`julia/`, module `Sugarscape`), `Test`, bash runner scripts beside the results as in stages 3 and 4.

**Spec:** `docs/superpowers/specs/2026-11-03-xxl-trade-design.md` (approved by the user). Read it first; this plan argues from it.

## Global Constraints

- Julia only. Python, the viewer and FLAME GPU are untouched.
- With Rule 13 off, every run's CSV stays byte-identical and every fingerprint unchanged: `julia/test/test_xxl_same_run.jl` digests and `julia/test/fixtures/xxl-v1/*.csv` must pass unchanged.
- `XXL_DEFAULTS` and `XXL_V1` don't change. Adoption is the user's decision after the findings.
- Rule T (`bargain!`) keeps its price, unit exchange, welfare tests and once-per-neighbour order. It may only record prices.
- Suite: `julia --project=julia -e 'using Pkg; Pkg.test()'` (about 12 min), run in the background, before every commit that touches `julia/src`. Commits need the user's approval (the user approved the design, not commits; ask once at the first commit whether task commits on the branch are approved).
- Work on a branch `xxl-trade` from `main` (51cbbb1 or later), in a worktree. Merging and pushing are the user's calls.
- Seeds: screening and Part 1 on 80–99, confirmation on 20–79 (extinction) and 0–19 / 20–39 (scorecards). Runs watched for memory, 5 workers.
- Bars and their constants are fixed in code (Task 7) before any screening run. Part 1 may change bar values once, recorded in the ledger and put to the user before screening (spec, "What Part 1 decides").
- Words in docs: plain, the style of `docs/xxl.md`; mark the user's decisions and my calls as the spec does.
- Pronouns: they/them for the user.

## Rulings made in this plan (*my calls*, against the spec's text)

- **The trace is the readings.** The spec's per-exchange trace on seeds 80–84 is folded into the trade readings (Task 5) on all 20 seeds of Part 1: every reading the spec lists comes from them, and no per-exchange file is kept. Cost if wrong: a reading nobody listed would need a rerun.
- **Confirmation's matched reading comes from its own 500-period run** on seeds 20–79 (Task 9), checked byte-identical against the extinction run's first 500 periods, instead of adding the readings to the extinction runner. The observer can't be paused, and the extinction runner pauses. Cost if wrong: about an hour of runs.
- **The blend is geometric** (Task 3), so it needs no units.
- **Remembered sites use the move's price** (Task 3).
- **Local price** is the latest exchange at each site in sight within the last 10 periods (Task 2), not every exchange.

## Review Focus

1. **An agent with no valid expected price** (no trades seen, MRS 0, Inf or NaN): it must score by the book's rule for that move, never NaN or Inf scores. Test in Task 3.
2. **A blend between 0 and 1 with a starving trip:** `net_value`'s `-Inf` for starving on the way must survive the blend (a negative or `-Inf` base can't be raised to a power). Test in Task 3.
3. **Checkpoints and resumes with the rule on:** an extinction run with Rule 13 stopped and resumed must give the same CSV as one that ran straight through (the new Agent and Model fields must be saved). Test in Task 2.
4. **Trade off and Rule 13 together:** a study arm with `--trade-off` and Rule 13 set must run as plain trade-off (the rule reset by `to_xxl`), and its fingerprint must say so, not refuse. Test in Task 4.
5. **An extinct or short seed in a study folder:** the report must leave it out of ratios with a note, as `disease_list.jl` does, never crash or count zeros. Test in Task 7.

### Task 3: The score that counts on trade

**Files:**

- Test: `julia/test/test_xxl_trade_move.jl` (new)

**Interfaces:**
- Consumes: Task 1's fields, Task 2's `expected_price`.
- Produces: `SiteWelfare(m, a)` unchanged in meaning (λ = 0); `SiteWelfare(m, a, looked)` builds the rule's version: λ = `trade_blend` and `inv_p = 1 / expected_price(...)`, except λ = 0 when the rule is off, the price is NaN, or the guard holds (`a.sugar < k * sugar_burn(a) || a.spice < k * a.spice_metabolism`).
- Produces: the two-good value, for parts A, B (after travel, as `net_parts` gives them) or `base + site` in `score`:
  - λ == 0: exactly today's expression (same operations, so bytes don't move).
  - λ > 0: `W^(1 - λ) * V^λ` with `W = A^e1 * B^e2` and `V = A + B * inv_p`. Both are of degree 1 in (A, B), so the blend needs no units (*my call*: the spec left the blend's form to the builder; this one is 0 at λ = 0, the full rule at 1, and ranks like value at 1).
  - starving on the way stays `-Inf` before any blending.
- Produces: in `speed_move!`, `sw` is built after `look!` (it draws nothing, so the stream is unchanged) and the `surely_less` pruning runs only when `sw.lambda == 0`. `remember!(m, a; sw)` ranks with the move's `sw` (*my call*: remembered sites are judged at the same price as the move).
