# VI-1 with combat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Julia-only experiment `VI-1-combat`: VI-1 with rule C_∞, where the attacker takes all of the victim's sugar
and spice, with no replacement. It runs in the book's world, xl and xxl through the combat study.

**Architecture:** Rule C gains a two-good path in both combat moves, the book's `combat_move!` and `xxl_combat_move!`:
- wealth is sugar + spice;
- the loot is added to the site's value;
- landing harvests through `harvest!`, so income is recorded and credit works.

The sugar-only path stays draw for draw as it is, guarded by byte-identical fixtures recorded before any change. The
experiment is a small Julia-side `Experiment` that only the combat study looks up.

**Tech Stack:** Julia, module `Sugarscape` in `julia/`, Test stdlib.

**Spec:** `docs/superpowers/specs/2026-11-08-vi1-combat-design.md`

## Global Constraints

- **Nothing that ran before changes.** Every combat experiment (III-9, III-11, III-12, III-13, III-14) in the book's
  world, xl and xxl, and VI-1 without combat, gives byte-identical CSV contents before and after. Fingerprint files carry
  a code hash and may change.
- **No change** to `XXL_DEFAULTS`, VI-1, the scorecard, the combat report, the Python model or the exported
  `julia/registry.toml`.
- **With spice on**, C_α takes min(α, victim's sugar) sugar and min(α, victim's spice) spice. `VI-1-combat` uses
  α = ∞.
- **Wealth** = sugar + spice with spice on, else sugar. It decides who can be attacked (occupant's wealth ≤ attacker's)
  and retaliation (another tribe's agent in sight with wealth > attacker's wealth after taking the site and the loot).
- **Loot** is not income and is not devalued by pollution. Landing harvests through `harvest!`.
- **The victim dies through `die!`**, with its loans settled as on any death. The kill is pushed to `m.killed`.
- **Experiment id `VI-1-combat`:** rules `({G1}, {C_∞, S, K, T, L10,10, E})`, 500 steps, 5 seeds, `replacement = false`.
  Its fingerprint is VI-1's plus one line, so its results never pass for VI-1's.
- **No study run.** Suite runs and scratch dry runs are fine.
- **Suite:** `julia --project=julia -e 'using Pkg; Pkg.test()'`. A single file:
  `julia --project=julia -e 'using Pkg; Pkg.test(test_args=["<substring>"])'`; runtests.jl filters by substring.

## Review Focus

1. **A victim holding spice but no sugar, on a bare site.** `score`'s shortcut for a site with no sugar and no spice
   (`sw.w0`) must not hide the loot. The test is in Task 2 (`test_loot_on_bare_site_counts`).
2. **The attacker is the victim's lender or borrower.** The loan is settled as on any death, and the attacker's own loan
   records stay consistent. The test is in Task 2 (`test_victim_loans_settled_as_on_death`).
3. **A killed victim later in the same period's order.** It never acts. The test is in Task 4
   (`test_vi1_combat_victim_never_acts`).
4. **The xxl path when the attacker would starve on the way** (the spice `net_value` is −Inf). The candidate is
   skipped, not taken. The test is in Task 3 (`test_xxl_spice_starving_trip_skipped`).
5. **Memory under spice.** A remembered site is valued with its remembered spice, devalued as `speed_move!` does, and
   `remember!` gets `sw`. The test is in Task 3 (`test_xxl_spice_memory_valued_with_spice`).

  g1 = g2 = 0, and takes the `w0` shortcut only when the site and the extra goods are all zero.
