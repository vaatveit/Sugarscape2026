# xl on FLAME GPU 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the xl (500×500) version of the Chapter II experiments on the GPU with `docs/xl.md`'s timing measures,
with no host copies sized for the 2500×2500 maximum, and validate the results statistically against Python's xl
runs.

**Architecture:**
- **C++.** The program gains a `diffusion_passes` key, run by a small diffusion sub-model. Host-side work stops
  touching site-sized macro properties: replacement reads citizen positions as agent data, and initialisation and
  site occupancy move into device layers. `--timing` gains setup, stepping and metrics.
- **Python bridge.** It gains `--xl` (through the Python project's own `to_xl`) and writes `timing.csv` and
  `machine.txt`. A one-off `bridge.xl_validate` compares GPU and Python xl results and writes the validation report.

**Tech Stack:** CUDA C++ (FLAME GPU 2 v2.0.0-rc.5, CUDA 13.4), Python 3 (numpy, pytest), the Python Sugarscape
project in the repository root.

**Spec:** `flamegpu/docs/superpowers/specs/2026-10-24-xl-gpu-design.md` (and `docs/xl.md` in the repository root).

## Global Constraints

**Paths and commands.**
- All paths are relative to `flamegpu/` unless they start with the repository root (`../`).
- The commands below run from `flamegpu/`. Python is `.venv\Scripts\python`.
- Build with `scripts\build.cmd` (`build\`, seatbelts on). Tests that use the fast build also need
  `scripts\build.cmd build-fast OFF`.

**Platform** (as Phase 1):
- FLAME GPU 2 v2.0.0-rc.5, CUDA 13.4, RTX 4080 (compute capability 89);
- telemetry off;
- look FLAME GPU APIs up in Context7 (`/websites/flamegpu`) before writing code that uses them.

**Results.**
- **No 50×50 result changes.** Every existing GPU run gives byte-identical output, so the saved `results-gpu/` stay
  current and the Phase 1 fingerprint (`gpu-phase1`) stays.
- **No Python project change.** Nothing outside `flamegpu/` is edited. The bridge calls
  `experiments.run.experiment_config(id, xl=True)`, `fingerprint(id, xl=True)` and `load_results` as they are.
- **Never drop a setting silently.** Any Config field the GPU does not read is refused when it isn't at its default.
  `sugar_map` and `diffusion_passes` become read fields; nothing else changes.

**Code rules.**
- Within one layer, a macro property is only read or only atomically written (the Phase 1 rule).
- No host function in setup or in a period touches a macro property declared with `MAX_CELLS` elements. The only
  exception is `src/checks.cu` (diagnostics: dumps and `--check`).
- Timing measures (spec section 4):
  - `setup_s`: from before `load_map` in `main` to the t = 0 state, with the t = 0 metrics left out;
  - `stepping_s`: the sum of each period's time, measured with the GPU synchronised;
  - `metrics_s`: the sum of the time spent gathering metrics (the agent copy plus `compute_metrics`), with the CSV
    write left out.
- Fidelity thresholds (spec section 5): a comparison **disagrees** when its gap is over **1%** of the metric's scale
  *and* |Welch t| > **3**. Checkpoints are at 10%, 25%, 50% and 100% of the periods.

## Review Focus

1. **A map whose size doesn't match the configured world**, such as `sugar_map = "sugar-map-xl.txt"` at 50×50: exit 2
   with a message naming the map, never a run on a misread map. Pinned in Task 6.
2. **`diffusion_passes` above 1 when diffusion is off**, or in periods without diffusion: pollution stays exactly as
   with 1 pass. Pinned in Task 3.
3. **A newcomer's site must be occupied before the next period's movement**, or two agents end up on one site:
   `--check` stays clean over a replacement run. Pinned in Task 4.
4. **Adding a second sub-model changes the movement sub-model's random stream**, since FLAME GPU reseeds sub-models
   in map order. Then every 50×50 result changes. Pinned by Task 1's golden runs, rechecked in Task 3.
5. **Timing taken with `--jobs` above 1**: `machine.txt` says the runs shared the GPU, so nobody reads them as solo
   timings. Pinned in Task 6.

### Task 3: Diffusion passes (the diffusion sub-model)

**Files:**
- Modify: `src/model.cu` (`describe_diffusion`, the sub-model, the new environment properties)
- Modify: `src/rules.cuh` (`diffuse`, `diffuse_commit`, exit condition `diffusion_done`)
- Modify: `src/host_state.cu` (`begin_period` sets the pass properties)
- Modify: `tests/reference.py` (`config_from_cfg` reads `diffusion_passes`, default `"1"`)
- Test: `tests/test_parity.py` (new cases)

**Interfaces:**
- Consumes: `RunConfig::diffusion_passes` (Task 2).
- Produces: environment properties `extra_passes` (`unsigned int`, the passes after the first) and `diffusion_pass`
  (`unsigned int`, a counter), both declared in the main model and in the sub-model.

**Design.**
- Pass 1 stays where it is: `cell_grow` reads `pollution` and writes `pollution_next`, and `cell_commit` copies the
  result back.
- A sub-model named `pollution_diffusion` runs the remaining passes. It binds `cell`, maps its environment with
  `SubEnvironment(true)`, and declares `pollution` and `pollution_next` as macro properties.
  - Layer 1, `diffuse`: if `diffusion_pass < extra_passes`, it writes the mean of the four von Neumann neighbours of
    `pollution` to `pollution_next[i]`. The arithmetic and wrap match `cell_grow`'s exactly.
  - Layer 2, `diffuse_commit`: under the same guard, it copies `pollution_next[i]` to `pollution[i]`.
  - Exit condition `diffusion_done`: it increments `diffusion_pass`, and returns EXIT when the counter is
    ≥ `extra_passes`. So a period without extra passes runs one step of early-returning kernels.
- `begin_period` sets `extra_passes = diffusing ? diffusion_passes − 1 : 0` and `diffusion_pass = 0`.
- The sub-model's layer goes last in the main model, after `cell_commit`.

  `host_state.cu`)

**Interfaces:**
- Produces:
  - host function `finish_init`, which at step 0 only writes the t = 0 dumps, invariants and metrics, and sets
    `RunState::population`;
  - `RunState::setup_end`, a `std::chrono::steady_clock::time_point` recorded in `finish_init` after
    `cudaDeviceSynchronize()`, which Task 5 times setup against.

**Layer order:**
1. `begin_period` (host): also sets `initialising = (step == 0)`;
2. `initialise`: `cell_initialise` and `occupy_site`;
3. `finish_init` (host);
4. `start_period`, the movement sub-model, `count_neighbors`, `metabolize_and_age`, `replace_dead` (host): as now;
5. `occupy_site`;
6. `cell_grow`, `cell_commit`, the diffusion sub-model.

**What each function does:**
- `cell_initialise`: when `initialising`, it writes `sugar[i] = capacity`, since sites start at capacity (p.21).
- `occupy_site`: every citizen writes `occupied[x + y·w] = 1`. In every period this only reaffirms sites already
  marked and marks newcomers. It is the same function in both layers; FLAME GPU forbids a function only twice in the
  *same* layer.
- `replace_dead`:
  - It copies the living citizens' `x` and `y` from `getPopulationData()` into a local occupancy vector, in a scope
    that closes before any `newAgent()`.
  - It lists the empty sites in ascending site order, then draws exactly as now.
  - It no longer writes `occupied`.

### Task 8: The comparison and the report (`bridge/xl_validate.py`)

**Files:**
- Create: `bridge/xl_validate.py`
- Test: `tests/test_xl_validate.py`

**Interfaces:**
- Consumes:
  - `run_experiment_gpu` and `default_out_gpu` (Task 6), and `EXE` and `FAST_EXE`;
  - `experiments.run.load_results(exp_id, out_dir)` and `results_current(exp_id, out_dir, xl=True)`.
- Produces:
  - `EXPERIMENTS_XL = ("II-4", "II-4-gini", "II-6", "II-7", "II-8")` and `SMOKE = "II-5/m3/v10.5"`;
  - `checkpoints(steps: int) -> list[int]`, which rounds 10%, 25%, 50% and 100% of `steps` to whole periods;
  - `@dataclass Comparison(exp_id, metric, t, gpu_mean, py_mean, gap_pct, welch_t, verdict)`, where `gap_pct` is a
    percentage, `welch_t` is a `float` or `None`, and `verdict` is `"agrees"`, `"disagrees"` or `"not judged"`;
  - `compare(exp_id, gpu: list[Series], py: list[Series], steps: int) -> list[Comparison]`, over every metric
    column both sides have except `t`;
  - `render_report(comparisons, smoke_ok: bool, timings: dict, machine: dict) -> str`;
  - `main(argv=None)`.
- The rules:
  - **Scale:** the largest |Python mean| over the whole run.
  - **Gap:** 100·|g − p| / scale.
